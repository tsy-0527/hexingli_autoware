# D455 三类检测 · ROS 2 Humble

适用小车为 Ubuntu 22.04 x86_64、ROS 2 Humble 和 D455。解压到自己的目录，例如 ~/d455_ws，保留整个文件夹。以下命令在能看到 build.sh 的目录执行。编译后请保留目录位置。

## 1　首次编译

安装了 ROS Humble 的小车先执行 bash build.sh。它创建项目虚拟环境，首次需联网安装 CPU 推理依赖，加载包内 best.pt，然后运行 colcon build。如果已装好之前的三类 Ubuntu 软件，可以指定它的解释器，省去重新下载模型依赖：

```bash
D455_PYTHON="/旧三类软件实际目录/.venv/bin/python" bash build.sh
```

若缺少系统工具，按需安装 python3-colcon-common-extensions、python3-venv、ros-humble-ament-cmake、ros-humble-message-filters、ros-humble-rqt-image-view。需要独立启动相机且系统查不到 realsense2_camera 时，再安装 ros-humble-realsense2-camera。已有 Autoware 相机驱动的机器请复用原环境。

## 2　启动

在小车平常使用 Autoware 的终端加载本包，并列出已有相机话题。多终端使用同一 ROS_DOMAIN_ID 和中间件设置。

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 topic list -t | grep -E 'color/image_raw|aligned_depth_to_color|camera_info'
```

**A · 小车相机驱动正在运行。** 彩色与对齐深度均来自 /sensing/camera/camera0 时：

```bash
ros2 launch d455_perception field.launch.xml
```

若两条输入实际在 /camera/camera 下，用：

```bash
ros2 launch d455_perception field.launch.xml camera_ns:=/camera camera_name:=camera
```

非标准命名可传 color_topic:=/实际彩色话题 depth_topic:=/实际对齐深度话题。如果只有彩色和原始深度，请在已有相机驱动中启用 align_depth.enable，可先用 ros2 param list /sensing/camera/camera0 查看是否支持该参数，再用 ros2 param set /sensing/camera/camera0 align_depth.enable true。对齐深度必须使用彩色光学坐标系，像素分辨率与彩色相同。

**B · 相机空闲。** 退出独占相机的旧录制窗口，确认 Autoware 未使用该相机，再同时启动相机驱动和检测：

```bash
ros2 launch d455_perception field.launch.xml start_camera:=true
```

驱动占用 D455 一次。驱动发布原始相机数据，检测节点订阅彩色及对齐深度。停止用 Ctrl+C。

## 3　查话题、看画面

另开终端，在本目录重新 source /opt/ros/humble/setup.bash 和 source install/setup.bash。

| 默认话题 | 消息类型 | 数据 |
|---|---|---|
| /sensing/camera/camera0/color/image_raw | sensor_msgs/msg/Image | 原始彩色图 |
| /sensing/camera/camera0/aligned_depth_to_color/image_raw | sensor_msgs/msg/Image | 对齐彩色的深度图，16 位毫米 |
| /sensing/camera/camera0/color/camera_info | sensor_msgs/msg/CameraInfo | 彩色相机内参 |
| /d455_perception/image_annotated | sensor_msgs/msg/Image | BGR8，三类检测框、置信度、Z 估计；沿用彩色帧 header |
| /d455_perception/detections | std_msgs/msg/String | JSON，每对成功处理的帧均发送，无目标时 detections 为空数组 |

```bash
ros2 run rqt_image_view rqt_image_view /d455_perception/image_annotated
ros2 topic echo /d455_perception/detections --once
ros2 param set /d455_perception confidence 0.45
```

查看器占用终端，后两条在另一个已加载环境的终端执行。若图像话题存在但无画面，检查输入是否有数据、两路时间戳差是否小于 20 ms、对齐坐标系是否一致；查看器的图像订阅使用 Best Effort。检测 JSON 使用 Reliable。输入源变更时，相机话题前缀随驱动而变。

JSON 含彩色与深度的时间戳、frame_id、每帧实际阈值、处理耗时，以及每个框的类别、像素坐标、置信度和 roi_median_z_m。默认阈值严格大于 0.40，Z 是框中心区域深度的中位数（米），深度不足为 null。原始相机发布频率与 CPU 检测输出频率可分别测量。

## 4　留一段联调数据

```bash
ros2 bag record -o field_test_01 /sensing/camera/camera0/color/image_raw /sensing/camera/camera0/color/camera_info /sensing/camera/camera0/aligned_depth_to_color/image_raw /d455_perception/image_annotated /d455_perception/detections
```

Ctrl+C 保存。下次换新的输出目录名。小车端验收以相机持续发布、带框画面可见、JSON 持续更新为准。
