# MID360S + FAST-LIO 本机建图操作流程

本目录已针对这台机器配置好以下链路：

```text
MID360S PointCloud2 + IMU
        ↓
FAST-LIO 稠密世界系点云 /cloud_registered + /Odometry
        ↓
MCAP rosbag
        ↓
bag2dufo →（可选 DUFOMap）→ mapclean → 栅格预览
        ↓
CloudCompare 人工复核 → 地图包 + validate
```

## 0. 已完成的本机适配

- 驱动沿用 `/home/tang/fastlio_ws/scripts/01_livox_driver.sh`，输入类型为 `sensor_msgs/msg/PointCloud2`。
- 建图使用 `config/fastlio_mid360s_mapping.yaml`，其中 `lidar_type=4`、`dense_publish_en=true`。
- 固定 FAST-LIO 外参与后处理外参为同一组值，避免 `/Odometry` 换算雷达位姿时不一致。
- 录制默认保存到 `/home/tang/fastlio_ws/bags/mapping/<地图名>_<时间>/bag`。
- 录制会自动归档 FAST-LIO YAML、Livox JSON、在线参数、节点列表和 bag 统计。
- 不使用原来的 `03_record_rosbag.sh`；它没有地图名、磁盘门槛和录后频率检查，也不会自动接入本工具的工作目录。

### 本机录制空间

已创建专用目录：

本机只有一块约 512 GB 的 Kingston SSD，系统、FastLIO、录包和后处理都位于同一块盘。2026-11-16 检查时可用空间约为 117 GB，没有发现已挂载的外置数据盘。录制脚本会在该目录下自动建立互不覆盖的时间戳会话，例如：

## 1. 正式录制前只需确认两项实车尺寸

打开 `config/postprocess.yaml`，复测：

1. `lidar_height`：平地到 MID360S 光心的垂直距离。当前值为 `0.51 m`。
2. `body_box_in_lidar`：以雷达光心为原点，`x` 向前、`y` 向左、`z` 向上，量车身最前/最后/最左/最右/最低/最高边界，再各留约 5 cm。

当前车体框为 `x=[-0.80, 0.25]`、`y=[-0.35, 0.35]`、`z=[-0.60, 0.10]`。它与本机 Hunter SE 的大致尺寸相符，但必须以雷达真实安装位置复核。框太小会留下车体点，框太大会误删近处墙面。

然后运行：

```bash
cd /home/tang/autoware_map/map_task4/mapping_tools
./check_setup.sh
```

录制脚本默认要求开始时至少还有 60 GB。每次录制前都重新检查；若不足，请先清理磁盘，或把录包写到容量足够的 SSD：

```bash
export BAG_ROOT=/挂载点/mapping_bags
df -h "$BAG_ROOT"
```

建议每小时至少预留 50 GB，并额外预留后处理空间。不要录到 U 盘。

## 2. 场地准备

- 把导航要通过的门固定在全开状态；可移动物品放到日常位置。
- 清走跟车人员和临时推车，关闭 Nav2、相机感知等高 CPU/磁盘负载程序。
- 选择固定、可复现的起点；需要室内外衔接时优先选门口控制点。
- 一张地图只录一个 bag。大区域宁可规划完整闭环，不要在录制中重启 FAST-LIO。

## 4. 开始录制

第三个终端执行（地图名只用字母、数字、下划线）：

```bash
cd /home/tang/autoware_map/map_task4/mapping_tools
./record_mapping.sh task4_floor1 "一层，门全开，起点=东门"
```

脚本会先检查 `/livox/lidar`、`/livox/imu`、`/cloud_registered`、`/Odometry` 是否真的有数据，并确认原始雷达话题为 PointCloud2。预检通过后才会录制。

行驶要求：

- 起步前静止 10 秒；速度不超过 0.5 m/s，转弯不超过约 30°/s。
- 起点 → 所有区域 → 回到起点，形成闭环；回到起点后再静止 10 秒。
- 长走廊来回各走一次，尽量看见端部、门框或柱子。
- 每个房间绕一圈；门口来回两次；所有站点、限速区和交接点都要到达。
- 跟车人员保持在车后，不要持续进入雷达前方。

回到起点并静止 10 秒后，在录制终端按一次 `Ctrl+C`。不要直接关闭终端。脚本会安全结束 MCAP，随后检查约 10 Hz 雷达/点云/里程计和约 200 Hz IMU。

录制结果示例：

```text
/home/tang/fastlio_ws/bags/mapping/task4_floor1_20261116_143000/
├── bag/
└── meta/
```

若任一频率低于期望的 95%，建议现场重录。

## 5. 自动后处理

假设上一步目录为 `$SESSION`：

```bash
export SESSION=/home/tang/fastlio_ws/bags/mapping/task4_floor1_20261116_143000
cd /home/tang/autoware_map/map_task4/mapping_tools
./postprocess.sh "$SESSION/bag" "$SESSION/work"
```

本机暂未发现 DUFOMap。未设置 `DUFOMAP_BIN` 时脚本仍会运行，但使用 `raw_merged.pcd`，随后依靠离群点、地面下反射和行驶通道检查清理；人员等动态物体的去除效果会弱一些。安装 DUFOMap 后可这样启用：

```bash
export DUFOMAP_BIN=/实际路径/dufomap/build/dufomap_run
export DUFOMAP_CONFIG=/实际路径/dufomap/assets/config.toml
./postprocess.sh "$SESSION/bag" "$SESSION/work"
```

完成后重点查看：

- `work/clean/mapclean_report.md`：地面高度、轨迹高度波动、回起点漂移警告；
- `work/clean/map_leveled.pcd`：自动清理后的主地图；
- `work/clean/suspicious.pcd`：被删除的可疑点；
- `work/clean/grids_preview/nav_grid.pgm`：导航二维预览。

若报告中实测雷达高度与 `0.51 m` 相差超过 5 cm，先修正配置，再从原 bag 重跑，不要继续打包。

## 6. CloudCompare 人工复核

本机当前未发现 CloudCompare。安装后同时打开 `map_leveled.pcd` 和 `suspicious.pcd`：

- 删除残留行人、推车、车体点和孤立飞点；
- 重点检查玻璃门、玻璃墙和镜面附近；必要时补齐玻璃墙边界；
- 检查门洞是否真实可通行，不能把打开的门误补成墙；
- 只删除或补必要障碍，不要整体平移、旋转或缩放点云，否则轨迹和 `T_old_to_new` 会失配；
- 另存为 PCD，例如 `$SESSION/work/edited_task4_floor1.pcd`。

## 7. 区域标注、打包和校验

先复制区域模板：

```bash
cp config/zones_template.yaml "$SESSION/work/zones.yaml"
```

在 CloudCompare/RViz 中读取地图坐标，填写房间、走廊、站点、限速区和交接点。随后执行：

```bash
python3 build_map_package.py \
  "$SESSION/work/edited_task4_floor1.pcd" \
  "$SESSION/work/clean" \
  task4_floor1 v1.0 \
  --zones "$SESSION/work/zones.yaml" \
  --bag "$SESSION/bag"
```

脚本会重新生成导航/定位栅格、限速掩膜、带 SHA-256 的 manifest，并自动运行地图校验。若要单独复验：

```bash
python3 validate_map.py <生成的地图包目录> --bag "$SESSION/bag"
```

只有以下项目都通过后才上车：轨迹位于可通行区、站点在空闲格、原始扫描与最终点云有足够一致性。之后再依次做 NDT 回放、初始定位、门口规划和低速实车测试。

## 8. 常见问题

- **提示磁盘不足**：清理到至少 60 GB，或设置 `BAG_ROOT` 到大容量 SSD；不要降低门槛后长时间硬录。
- **提示雷达类型不符**：只运行本目录的启动脚本，确认驱动为 PointCloud2 模式，不要混用 CustomMsg 启动方式。
- **缺少 `/cloud_registered`**：FAST-LIO 未成功启动或配置加载失败，查看第二个终端错误。
- **bag 后处理提示时间戳无法匹配**：检查雷达/IMU时间同步和系统时间；不要随意放宽 `max_stamp_dt`。
- **地图稀疏**：确认启动日志使用本目录 YAML，且 `dense_publish_en=true`。
- **清理误删墙面**：复测 `body_box_in_lidar`，尤其是雷达到车头/车尾的 x 范围，并检查 `route_shrink`。
- **想保留原始数据离线重跑**：当前本机原始话题是 PointCloud2，必须用同一套 `lidar_type=4` 配置回放；不能照工具包原说明直接切到 Livox CustomMsg 模式。
